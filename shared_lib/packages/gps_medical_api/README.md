## Pays & résidence des données (v1.1.0)
Chaque compte porte un `country` immuable (`DZ` | `TN`) fixé à l'inscription.
- `DZ` → `data_residency_mode=device_only` : champs de profil restreints et
  documents médicaux ne sont **pas** stockés côté serveur (voir addendum-1.1.0).
- `TN` → `data_residency_mode=server` : comportement serveur inchangé.
Voir `docs/api/addendum-1.1.0.md`.

## Spécialistes Tunisie — quarantaine (v1.1.1)
`role=specialist` + `country=TN` est **accepté** à l'inscription. Un dossier
TN approuvé par un admin reste en `approved_pending_activation` (`verified=false`)
tant que le flag serveur `TN_SPECIALIST_ACTIVATION` est off — ces médecins
n'apparaissent sur aucune surface patient (`/doctors`, `/search/doctors`,
`/geo/doctors/nearby`, `/search/suggest`) et ne sont pas réservables.
Voir `docs/api/addendum-1.1.1.md`.
